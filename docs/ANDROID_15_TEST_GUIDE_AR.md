# اختبار النسخة التجريبية على Android 15

الحزمة `org.erthi.noor`، الإصدار `0.1.0-alpha`. نزّل ملف Debug من التشغيل الذي يطابق مراجعة الكود وافتحه على هاتف اختبار. عند التنزيل من GitHub Actions فك ضغط `TEST-ONLY-debug-apk` أولًا وقارن بصمة `app-debug.apk` مع `SHA256SUMS`.

إذا رفض Android التحديث بسبب اختلاف التوقيع، استخدم هاتف اختبار أو ملف مستخدم منفصل. إزالة النسخة القديمة تحذف بياناتها المحلية. اختبر باستخدام بيانات تجريبية.

## المسارات الأساسية

- اختر سورة الإخلاص ثم الآية الثانية بالبحث عن `112:2`. جرّب السابق والتالي وحدود أول وآخر آية.
- تقدّم من القراءة إلى الاسترجاع، ثم اختر «أعد المحاولة». كرّر الدورة واختر «جيد» وتحقق من حفظ المراجعة.
- غيّر اللغة ثم أدر الشاشة. انتقل إلى الشاشة الرئيسية للهاتف، ثم أوقف التطبيق من إعدادات Android وافتحه مجددًا. تحقق من بقاء موضع الآية ومرحلة الحفظ وجدول المراجعة.
- قارن النص المعروض بمصدر موثوق. تأكد مع TalkBack أن الاسترجاع لا يقرأ النص المخفي.

- جرّب الوضع الفاتح والداكن والتباين المرتفع، وخط النظام 200٪، والهاتف بوضعَي الطول والعرض.
- اختبر العربية أو الأردية ثم الإنجليزية مع TalkBack. تحقق من ترتيب التركيز وأسماء الأزرار وإعلان حالة المفاتيح وعدم وجود نص مقطوع.
- افصل الإنترنت وأعد فتح التطبيق. دوّن إصدار Android والطراز وأرقام الخطوات والنتيجة المتوقعة والفعلية.

## الإبلاغ عن عطل

أرسل خطوات التكرار وإصدار التطبيق والطراز عبر `admin@erthi.org`. إذا احتجت Logcat، شغّل التطبيق ثم نفّذ من حاسوب متصل عبر USB:

```sh
adb shell pidof -s org.erthi.noor
adb logcat --pid=PID -v brief AndroidRuntime:E '*:S'
```

استبدل `PID` بالرقم الناتج، ثم أعد تنفيذ الخطوات وأوقف التسجيل. إذا اختفت العملية، راجع مخزن الأعطال محليًا عبر `adb logcat -b crash -d -t 100` وانسخ فقط أسطر الحادثة الخاصة بالحزمة بعد مراجعتها. احذف أي بيانات شخصية أو أسماء حسابات أو معرّفات أجهزة أو مسارات خاصة. أرسل مقتطف العطل فقط، وتجنب إرسال سجل النظام الكامل أو لقطات تتضمن إشعارات شخصية. أوقف تصحيح USB بعد الاختبار.
